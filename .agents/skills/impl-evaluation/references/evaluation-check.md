# impl-evaluation reference

## 評価手順

1. `git log` と Generator Output の commit 一覧が対応しているか確認する
2. 対象 commit の差分を確認する
3. issue スコープ外の変更がないか確認する
4. 受け入れ条件ごとに結果を記録する
5. 検証コマンドを実行した場合はコマンドと結果を記録する
6. 検証を実行しない場合は理由を記録する
7. 発見事項を `修正必須`、`任意改善`、`blocked` に分ける

## 評価観点

- 受け入れ条件を満たしているか
- 差分が issue スコープ内に収まっているか
- Planner の実装契約を満たしているか
- 実装が既存設計・コードスタイルに合っているか
- 機能仕様や責務の変更に対して必要なドキュメントが更新されているか
- 必要な検証が実行されているか、または未実行理由が妥当か
- 回帰リスクや未解決事項が PR 前に許容できる状態か
- unrelated changes を巻き込んでいないか

## Result 判断

- `pass`: 受け入れ条件を満たし、差分が issue スコープ内で、PR 作成を妨げる未解決事項がない
- `needs-fix`: issue スコープ内の修正で解消できる不具合、不足、検証漏れがある
- `blocked`: 受け入れ条件やスコープの変更、人間判断、外部状態、権限、データ破壊、セキュリティ判断が必要
