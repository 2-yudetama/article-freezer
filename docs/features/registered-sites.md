# 登録サイト

登録サイト機能は、ユーザが登録したサイトの RSS / Atom フィードに掲載された記事リンクを確認し、必要な記事を既存の記事保存フローへ渡す機能。

画面は `/users/[userId]/registered-sites` で提供する。既存のナビゲーションから開き、サイト選択とページ位置は URL の `siteId`・`cursor`・`mode` に反映する。タブ閲覧の開始時刻と新着判定の基準は画面の閲覧中だけ state に保持して API リクエストへ渡し、URL へは保存しない。新しいタブや URL の再訪では DB の前回アクセス日時と今回の DB 時刻から基準を作り直す。`cursor` がある URL の直接アクセスとブラウザの戻る・進むは DB キャッシュの読み取りとして扱う。

## サイト登録

サイト URL またはフィード URL を `POST /api/users/[userId]/registered-sites/discover` に渡して RSS / Atom の候補を検出する。フィード URL を直接渡した場合は、その URL を候補として検証する。候補が 1 件ならそのフィードを利用し、複数件なら画面で選択する。候補がある場合も、古いフィードや取得できないフィードを避けるためリンク登録を選択できる。候補がない場合やサイト本文を取得できない場合は、公開 URL の検査後にリンク登録へフォールバックする。

登録は `POST /api/users/[userId]/registered-sites` で行う。`feedUrl` が省略された場合は自動検出し、`feedUrl: null` の場合は明示的にリンクとして登録する。候補選択画面には検出元の登録 URL も表示し、入力した URL をブックマーク先として保存する。ユーザ単位でフィード URL のハッシュを一意にし、フィード非対応のリンクはサイト URL のハッシュを部分一意にする。同じユーザによる重複登録は `409` を返す。登録時に検証できたフィードの項目は初回キャッシュへ保存し、登録直後から一覧へ表示する。

## フィード取得

取得は Web アプリのサーバ側で行い、定期ジョブは使用しない。画面アクセス時は DB キャッシュを先に読み取り、キャッシュがない場合は初回 loading を返してクライアントが更新 API を待つ。期限切れキャッシュは既存一覧を表示したまま、クライアントが更新 API の完了を待って結果を反映する。ページ移動では取得 API を呼ばず、明示的な更新だけが外部取得を開始する。

外部取得には次の共通初期値を適用する。

| 制限 | 初期値 |
| --- | ---: |
| キャッシュ TTL | 1 時間 |
| 取得開始から次回取得まで | 60 秒 |
| 1 操作全体の期限（DNS・リダイレクト・本文・解析） | 50 秒 |
| 各 HTTP リクエストの期限 | 10 秒 |
| 応答サイズ上限 | 2 MiB |
| 解析可能な記事数 | 200 件 |
| リダイレクト上限 | 3 回 |
| 画面のページサイズ | 20 件 |

応答サイズ・記事数の上限を超えた場合や XML を解析できない場合は、結果全体を破棄して前回キャッシュを維持する。`ETag`・`Last-Modified` は利用しない。

ユーザ入力の URL は `http` / `https` に限定し、認証情報を拒否する。DNS 解決で私有・ループバック・リンクローカル・予約アドレスを拒否し、検査済み IP への接続を固定する。リダイレクト先も同じ検査を行う。

## キャッシュと新着

`registered_sites` の `fetch_token` と `fetch_not_before` を条件付き更新して、登録先単位の同時取得を抑止する。取得結果の保存は登録先をロックし、トークンが一致する場合だけ `feed_entries`、キャッシュ世代、最終成功日時、トークンを同じトランザクションで更新する。取得失敗時はトークンだけを一致条件付きで解除し、次回取得可能日時は早めない。

記事は RSS の `guid`、Atom の `id`、それらがない場合は記事 URLから識別する。同じ記事が継続して掲載される間は `first_seen_at` を維持し、フィードから消えた記事はキャッシュから除外する。再登場時は新しい記事として扱う。

タブアクセス時は `site_tab_states.last_accessed_at` を読み取り、新着判定の基準を固定する。初回アクセスではサーバが発行した `accessStartedAt` と同じ時刻を基準にする。画面に一覧または空状態を表示できた後、`POST /api/users/[userId]/registered-sites/access` で開始時刻を送信し、DB の `GREATEST` で前回値より後の日時だけを保存する。取得失敗画面では保存しない。記事の `first_seen_at` が基準より後なら「新着」を表示し、既読状態は保持しない。

## ページングと API

フィード全体を DB に保存し、公開日時がある記事は `published_at DESC NULLS LAST, entry_key DESC` の順で 20 件ずつ返す。公開日時がない記事は既知日時の記事の後ろにまとめ、同じ日時でも `entry_key` で順序を固定する。カーソルは登録先 ID、キャッシュ世代、公開日時（null を含む）、末尾記事のソートキーを含むバージョン 2 とする。世代が変わったカーソルは `409` とし、画面は先頭から読み直す。ページ移動では外部フィードを取得しない。

デスクトップでは登録先を 9 件ずつページ表示し、通常のデスクトップ・タブレット高さでは登録先 9 件とページ操作をスクロールなしで表示する。極端に低い画面だけは登録先一覧を内部スクロールに切り替え、記事一覧セクションのスクロールを妨げない。モバイルでは登録先を折り畳み、通常は選択中の登録先だけを表示する。記事ページを次へ移動したときは記事一覧の先頭へスクロールする。新着記事はカードのボーダー色と `新着` バッジで識別する。

ページ移動とブラウザの戻る・進むは常に `mode=page` の DB 読み取りとして扱い、先頭ページへ戻った場合も外部取得を開始しない。画面内で訪問したカーソル履歴はサイト切り替えやキャッシュ世代の変更で初期化し、履歴にないカーソルの直接アクセスは実際のページ番号を推測せず「ページ位置」と表示する。

| 操作 | API |
| --- | --- |
| フィード候補の検出 | `POST /api/users/[userId]/registered-sites/discover` |
| 登録・一覧取得 | `POST/GET /api/users/[userId]/registered-sites` |
| 登録解除 | `DELETE /api/users/[userId]/registered-sites/[registeredSiteId]` |
| 手動更新 | `POST /api/users/[userId]/registered-sites/[registeredSiteId]/refresh` |
| 閲覧開始時刻の記録 | `POST /api/users/[userId]/registered-sites/access` |

すべての API はセッションのユーザ ID と URL の `userId` が一致すること、対象登録先の所有者が一致することを確認する。外部取得は公開 URL 検査、DNS 固定、リダイレクトごとの再検査、時間・サイズ上限を適用する。取得・解析に失敗した明示的なフィード登録は `502` / `422` とし、画面からリンク登録へ切り替えられる。内部ネットワークや予約アドレスは `400` として拒否する。登録解除時は記事キャッシュも Cascade 削除するが、既存の `Article` は削除しない。

## 保存導線

記事カードの「保存する」は、記事 URL を `/users/[userId]/articles/registration?url=...` に渡す。既存の本文抽出・確認・コメント・タグ・保存フローはそのまま利用し、登録サイトのキャッシュには本文を保存しない。
