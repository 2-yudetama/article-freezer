# 記事詳細表示

## 概要

記事詳細表示機能は、ユーザが保存した特定の記事の本文、コメント、タグ、元記事リンクを確認し、コメントを追加・編集したり、記事を削除したりする機能。

画面は `/users/[userId]/articles/[article_id]` で提供する。

記事編集機能は、詳細画面から遷移した `/users/[userId]/articles/[article_id]/edit` で提供する。編集対象は記事タイトルと Markdown 本文だけとし、タグ、コメント、お気に入り状態、元記事 URL は編集しない。

詳細データは API route 経由ではなく、サーバ側で Prisma から直接取得する。

## 画面フロー

記事詳細表示は次の流れで表示する。

1. URL の `userId` と `article_id` を取得する
2. 指定ユーザが所有する記事を取得する
3. 記事に紐づく入力元、コメント、タグを取得する
4. 記事本文、コメント、タグ、元記事リンクを表示する
5. 必要に応じて詳細画面内でコメントを追加・編集する
6. 不要になった記事は確認ダイアログから削除する

記事が見つからない場合は 404 として扱う。

## データ取得

記事詳細ページでは、サーバ側で次のデータを取得する。

- 記事本体
- `article_sources`
- `article_comments`
- `article_tags_articles`
- `article_tags`

## 表示内容

記事詳細では次の項目を表示する。

- 記事タイトル
- 記事本文
- 投稿日
- 保存日
- 入力元の種類
- 元記事へのリンク
- コメントエリアへの移動ボタン
- お気に入り状態
- 紐づくタグ
- コメント
- コメント更新日時

元記事へのリンクは別タブで開く。

コメントエリアへスクロールするボタンは、元記事情報の表示領域とは分けて元記事リンクの上に表示する。

投稿日がない場合は `投稿日不明` と表示する。

お気に入り状態は、お気に入りの記事の場合のみ表示する。

コメントがない場合もコメント欄を表示し、詳細画面内で新規コメントを追加できる。

コメントがある場合は Markdown プレビューとして表示し、更新日時を表示する。

コメント欄では、表示状態から編集状態へ切り替えて、コメントを保存またはキャンセルできる。

編集状態では Markdown プレビューを確認できる。

コメント保存時は、入力値を前後 trim し、空白だけの入力は保存しない。

コメントは 1000 文字以内とし、1000 文字を超える入力は保存できない。

保存中、保存成功、保存失敗、キャンセルは画面上のボタン状態やトースト、エラー文言で分かるようにする。

タグを押すと、記事一覧のタグ絞り込みへ遷移する。

## コメント更新

コメント更新は詳細画面内で完結し、コメント編集専用 URL は持たない。

コメント保存処理は PATCH の API route 経由で行う。

保存時は URL の `userId` と `article_id` の組み合わせで記事所有を確認し、対象ユーザが所有する記事のコメントだけを作成または更新する。

`article_comments.article_id` は unique のため、既存コメントがある場合は更新し、コメントがない場合は新規作成する。

保存成功後は詳細画面のコメント本文と更新日時を最新状態へ反映する。

記事タイトル、本文、タグ、元記事 URL、お気に入り状態、削除処理はコメント更新では変更しない。

## 記事削除

記事詳細画面の削除ボタンを押すと、確認ダイアログを表示する。キャンセルすると記事は変更しない。

削除を確定すると、`DELETE /api/users/[userId]/articles/[articleId]` を呼び出す。API は既存のセッション認証と URL の `userId` 一致を検証したうえで、指定ユーザが所有する記事だけを記事 ID とユーザ ID の組み合わせで削除する。記事が存在しない場合や他ユーザの記事の場合は削除しない。

記事の削除により、外部キーの Cascade 設定に従って記事の入力元、コメント、タグとの関連も削除する。タグ本体と、同じタグを使う他の記事は保持する。

削除中は確定ボタンとキャンセルボタンを無効化して二重送信を防ぐ。失敗した場合はエラーをダイアログ内に表示し、ダイアログを開いたまま再試行できる。成功した場合は通知を表示し、記事一覧へ遷移して最新状態に更新する。

## 記事編集

編集画面はサーバ側で URL の `userId` と `article_id` に一致する所有記事を Prisma から取得して表示する。記事が存在しない場合や、指定ユーザが所有していない場合は 404 として扱う。

編集できる項目は次の 2 つ。

- タイトル
- Markdown 本文

元記事 URL は変更不可の項目として表示し、タグ、コメント、お気に入り状態は編集画面から変更しない。本文入力欄は常時表示し、Markdown プレビューだけ必要なときに開く。初期状態ではプレビューを描画しない。

保存は `PATCH /api/users/[userId]/articles/[articleId]` で行う。API はセッションの存在、URL の `userId` とセッションユーザの一致、対象記事の所有を順に確認する。タイトルは前後の空白を除去したうえで 1 文字以上 255 文字以内、本文は空白だけでないことを検証する。記事 ID とユーザ ID を条件にした単一の更新処理で `title` と `content` だけを更新し、`updated_at` は Prisma の `@updatedAt` に任せる。記事が存在しない場合や所有していない場合は 404、不正な入力は 400 を返す。

保存中は保存・キャンセルボタンを無効化し、二重送信を防ぐ。保存に失敗した場合は入力値を保持したまま画面にエラーを表示し、再試行できる。キャンセル時は API を呼び出さず詳細画面へ戻る。保存成功時は詳細画面へ遷移して再検証し、更新後のタイトルと本文を表示する。

編集ページのタイトルと保存・キャンセル操作を含むヘッダーは常時表示し、記事編集領域だけをスクロールする。

## 現状の注意点

記事詳細データの取得は専用の GET API route を持たず、サーバ側の page 実装から Prisma を直接呼び出している。記事削除は詳細画面から DELETE API route を呼び出す。

削除処理は詳細画面から API を呼び出して実行する。
