# 登録サイト UI モック

Issue #83 の画面構成と操作を検討するための草案。`index.html` をブラウザで開くと動作する。`styles.css` は同じディレクトリに配置する。ビルドやアプリの起動、外部通信は不要。

## 確認できる操作

- 左のサイト一覧を選択して記事一覧を切り替える
- テック観測所の 42 件を「次へ」「前へ」で 20 件ずつ表示する
- 「サイトを追加」で URL を入力し、フィード候補を選択して登録する
- 「リンクとして登録」でフィード非対応のサイトを追加する
- 「今すぐ更新」と「状態を試す」で更新中・取得失敗・一覧変更時の表示を確認する
- 記事の「保存する」で既存の登録画面へ進む操作の説明を表示する
- サイト名の右側の設定ボタンで、確認後に登録を解除する
- ブラウザの幅を狭めてスマートフォン向けの配置を確認する

## 仕様の前提

配信元の RSS / Atom はまとめて取得し、ユーザごとの登録先に紐付けてアプリの DB に保存した一覧から画面へ 20 件ずつ返す。配信元の過去記事をページごとに取得する仕様ではない。

「新着」は前回タブアクセス以降に一覧に加わった記事の目印であり、未読や公開日の新しさを示すものではない。サイト登録後に初めて取得した記事はすべて新着の対象となる。フィードから消えた記事の履歴は保持せず、再掲載は新着になり得る。実際のキャッシュと日時の設計は [DB 設計案](../registered-sites-db.md) を参照。

## モックの制約

記事・サイト・日時は架空のサンプルであり、フィードの取得や DB 保存は行わない。再読み込みで初期状態へ戻る。記事への移動・本文抽出・保存は説明メッセージだけで、外部ページへは移動しない。サムネイルは内製 SVG のプレースホルダー。

フィード検出は常にサンプルの 2 候補を表示する。通信・非対応の実判定、URL とページ位置の同期、前回アクセス日時の永続化、取得間隔の制限と取得トークンによる保存制御は本実装で対応する。最後の登録サイトはモック内では解除できない。初回読み込みと登録 0 件の専用画面は未作成。操作確認用の「状態を試す」は製品画面には含めない。
